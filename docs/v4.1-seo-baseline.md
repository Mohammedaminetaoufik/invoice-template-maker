# V4.1 SEO and conversion baseline

Baseline supplied for October 12–18, 2026: 242 Google impressions, no clicks, average position 85.6, and 81 visible queries. The site was approximately one week old, so these figures are directional rather than a stable forecast. The largest demonstrated opportunities are `/en/how-to-make-an-invoice/` (about 118 combined HTTP/HTTPS impressions), `/en/simple-invoice-template/` (43), `/fr/` (19), and the smaller but promising `/fr/facture-avec-logo/` sample.

## Strengths preserved

- Static English/French routes with server-rendered titles, descriptions, H1 content, canonical links, reciprocal hreflang, x-default, robots, and sitemap entries.
- Browser-local invoice editing, calculations, logo storage, PDF generation, draft persistence, reminder generation, and safe invoice-to-reminder transfer.
- One shared invoice layout engine for the browser preview and PDF.
- Existing OG artwork at 1200×630, a large-image X card, consent-gated GA4, PWA support, and validation-only GitHub Actions.
- Cloudflare Worker static-asset architecture with no backend or database.

## Weaknesses found before V4.1 changes

- The highest-impression invoice guide had only four short generic sections, no concise answer, no complete example, no real rendered invoice, and weak conversion paths.
- The simple-template page used a generic hero and placed its builder above only two short paragraphs; it did not prominently show or explain the minimal template. Its CTA could not guarantee the minimal layout when a saved draft used another design.
- The French homepage had useful generic three-step copy but no focused section with contextual links to the French simple, freelance, logo, and guide pages.
- The invoice-with-logo pages had no real visual example and did not explain supported formats, automatic placement, or local image processing.
- Conversion events for template selection, customization, successful PDF generation, reminder generation/copying, and invoice-to-reminder navigation were absent.
- Static verification checked route existence and common metadata but did not enforce exactly one H1, parse JSON-LD, or validate ordinary internal link targets.
- The real X card issue could not be reproduced from public HTTP checks: metadata and image responses were valid, which makes X-side caching a plausible but unprovable factor.

## Highest-impact implementation choices

1. Turn the indexed invoice guide into a complete task resource with an immediate answer, eight practical steps, a fictional invoice rendered by the production component, seven annotations, mistakes, FAQs, and direct tool paths.
2. Give the simple-template page an above-the-fold minimal preview and an explicit `template=minimal` CTA that changes only the layout and preserves draft data.
3. Add concise French homepage guidance and descriptive links without moving the generator from its primary position.
4. Add real logo-template examples and accurate local-processing guidance in both languages.
5. Add consent-dependent, anonymous outcome events without sending invoice or client data.
6. Strengthen build-time SEO assertions and use versioned OG filenames to offer crawlers a new cache key while retaining the approved image design.

## External limitations

No newer Search Console export was present in the repository. The local project cannot inspect Google indexing state, GA4 reports, X’s internal card cache, or Cloudflare account settings/build history. Public checks on October 21, 2026 confirmed exact HTTP→HTTPS 301 redirects (including path and query string), accessible root/EN/FR metadata, and successful full Twitterbot GET requests for both JPEGs.
